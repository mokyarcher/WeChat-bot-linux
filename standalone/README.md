# 独立运行层开发说明

架构与入口见 [项目说明](../README.md)，线上操作见 [部署维护](../部署维护.md)，待办统一见 [面板适配计划](../Linux面板适配计划.md)。

## 代码职责

| 文件 | 职责 |
|---|---|
| server.mjs | HTTP 服务、宿主接口适配、原插件 apply 加载、配置与动作白名单 |
| bowxt.mjs | 群范围约束、消息格式、长轮询、历史搜索、发送请求幂等与确认 |
| model.mjs / presets.mjs | OpenAI-compatible Chat Completions 与预设、密钥复用规则 |
| history.mjs | 当前群已记录消息的游标分页与逐页文字匹配，限制页大小、游标和群范围 |
| service-health.mjs | 显式开启后的 noVNC、Authelia 和 VNC 本机只读检查，30 秒缓存及并发合并 |
| persona-backups.mjs | 当前群人格快照列表/摘要、路径与双摘要校验、恢复前回退副本；不处理全量部署备份 |
| memory-backups.mjs | 当前群长期记忆整库快照、摘要预览、路径与双摘要校验、恢复前回退副本；不导出短期聊天或其他群数据 |
| setup.html | 模型配置、测试与启停首页 |
| bowxt-test-group-web.py | 接入包装入口、限制 chat_id=1、关闭自动发现、报告扫描完成、识别自身昵称 |
| wechat-soul.service / nginx-*.conf | 现有服务器模板，其他主机使用前需调整 |
| desktop-auth.service / nginx-desktop.conf | Authelia systemd 模板、网页桌面鉴权与 WSS 代理；nginx-https.conf 引用已安装的位置配置，部署前须准备认证服务 |
| prepare-management.py | 当前部署的初始化辅助脚本，不是完整安装或升级工具 |
| test/ | 假模型、假接入服务及时间/暂停边界回归 |

历史查询支持 since/until 标准 UTC ISO 边界（含开始、不含结束）；页面按北京时间日期生成边界，结束日期含当天。日期匹配只使用 observed_at，未知接收时间不猜测，回传 unknownTimeCount。仍按原始记录页推进游标，不根据非单调的微信分组时间提前终止分页。

业务在 upstream/wechat-bot/wechat-group-agent/lib，已有本地补丁，并非原样上游。修改面板后需要重新生成 lib/client.js。

## 启动

需要 Node.js 22+ 和已运行的 bowxt 服务。以下为 Linux shell 示例：

```bash
cd standalone
BOT_ROOT=.. BOT_DATA=./data node server.mjs
```

| 变量 | 默认值 / 含义 |
|---|---|
| BOT_ROOT | ..，包含 upstream/wechat-bot 的根目录 |
| BOT_DATA | ./data，私有数据目录，相对工作目录解析 |
| PORT | 18788，仅监听 127.0.0.1 |
| BOWXT_URL | http://127.0.0.1:8787 |
| BOWXT_CHAT_ID | 1；包装入口同样固定为 1，改变量不会自动开放其他群 |
| BOWXT_CHAT_NAME | 小鲸鱼调教，需与 bowxt 配置和微信标题一致 |
| PUBLIC_ORIGIN | 公网来源校验，线上为 https://chat-manage.sharex.team |
| DESKTOP_HEALTHCHECKS | 默认关闭，值为 1 时探测固定本机 6080、19091、5900，不执行登录或 UI 操作 |

进程将 DSH_HOME 指向 BOT_DATA，不需要安装 DSH。持久化配置覆盖代码默认值，因此仅改默认值不代表线上参数会随之变化。

## 配置与边界

首页提供模型预设与自定义接口。密钥保存于 BOT_DATA/model.json，状态只返回 hasKey；不同接口不能静默沿用旧密钥。当前部署用 DeepSeek，其余预设主要经模拟验证，不能保证实际账号已开通相应模型。

完整面板位于 /wechat-bot，操作受 supportedActions 和 editableConfig 限制。开放前必须核对实际实现、群范围、参数、持久化和错误反馈，而非只解除白名单。Linux 自检与真实接入状态已接通，客户端连接不等同于确认账号登录。

当前仅投递文字；跨群记忆关闭，昵称身份有同名/改名限制。消费 ACK 表示消息已持久化，不表示异步回复或记忆更新完成。退出恢复采用下述待核查机制，不自动重放。

记忆页支持当前群长期记忆的完整快照、摘要预览和恢复。创建/恢复前需暂停接入并确认 UI 工作线程空闲，恢复会先保存当前 facts 并更新业务内存缓存，之后保持暂停。快照目录为 `BOT_DATA/memory-snapshots/`，与单次低权重清理备份 `memory-backups/` 分开。当前不提供自动保留清理，也不包括短期对话、人格状态或模型配置。

手动页通过 /runtime/messages 查询最近和更早记录，仅限接入已记录消息，不是微信全量历史；关键词逐页匹配。手动 sendText 动作要求固定房间、纯文字不超过 2000 字和请求 UUID；总回复或接入暂停均阻止。相同 UUID + 文本沿用持久化发送请求，不同点击生成新 UUID；未确认请求保存在当前标签页 sessionStorage，成功后清除。出站映射中的 manual 项保留以支持跨时段重试，后续需补保留策略与容量维护。

服务启动后接入默认暂停，启用时先建立快照，再消费后续消息。业务回复开关与底层监听/发送暂停不是同一项控制。

## 验证

在 standalone 目录执行：

```bash
node --test test/*.test.mjs
```

需要回环通信和子进程权限。修改原面板/业务时，在 upstream/wechat-bot/wechat-group-agent 执行：

```bash
node build-client.mjs
node scripts/test-all.mjs
```

当前上游检查仅 5 项静态检查，不是全部历史单测。修改 bowxt 遵循其 AGENTS.md / AGENT.md；实机只在授权群低频验证。现有验证结果与原有失败项见部署维护文档。

## 发布维护规则

按 2026-11-06 用户要求，修改或发布不再例行在云服务器创建备份。先核对当前状态并尽量保留启停状态；出问题先询问用户，再决定是否用本地 Git 指定提交回退相关代码。Git 不恢复或覆盖运行数据、模型密钥、微信登录卷。面板人格/记忆快照及恢复前保护保持原有行为。详细规则见 [部署维护](../部署维护.md)。

## 轮次持久化与保守恢复

- `turns.mjs` 在 ACK 前把规范化消息写入 `BOT_DATA/turns/`：临时文件、fsync、原子替换，Linux 同步目录。写入失败停止消费并拒绝发送；损坏记录拒绝启动，不清空重建。
- 跟踪接收、合并等待、处理、完成、跳过和待核查。合并批次按群与消息 ID 序列生成标识，自动文字在入队时取得“批次 + 拆句序号”，避免共享发送队列串错异步上下文。原业务的人设、关系、记忆与回复策略保留。
- 重复投递只 ACK，不启动第二个业务任务。重启时未完成记录转待核查，不自动重新生成、发送或更新记忆。已完成文字回复保存当前群短期上下文后结束；定时记忆提炼仍使用原触发策略，不强制每条提炼。
- `send-requests.json` 保存稳定请求与后端 client_id 映射。确认成功后不再次提交；已知 seq 时查询原消息。发送错误停止出站队列自动重试；显式核查同一请求仍沿用原 client_id。同一标识不能换正文，新稳定映射不按旧的一分钟窗口清理。
- `GET /runtime/turns` 返回计数及最近 100 个待核查记录的元数据，不返回消息正文。`POST /runtime/turns/resolve` 要求安全暂停、无活动业务/待处理轮次，以及 id、updatedAt、confirm=true；只标记人工核查结束，不重发、不恢复数据，旧预览或重复提交拒绝。沿用网站认证与来源检查。
- 运维日志页提供待核查列表；统一诊断显示存储错误与待核查数量。人格恢复、记忆快照创建/恢复额外等待业务轮次及后台记忆提炼任务空闲。

这是保守恢复，尚未实现按阶段自动续跑、逐条出站结果核查工具、轮次/请求映射容量管理或独立定时任务的完整恢复。首次升级无法追溯旧代码未记录的轮次。不要手工删除这些运行数据；页面视觉验收由用户完成，发布结果见部署维护文档。

## 出站结果只读核查

运维日志的待核查轮次新增“核对发送结果”。GET /runtime/turns/outbound?id=... 只允许查询当前群待核查记录登记的出站标识，不接收任意后端消息编号。已知 seq 时 GET 原消息；响应丢失时按 client_id 搜索当前群最近 100 条。核对群、出站方向、请求标识和正文摘要，任一不符显示身份不一致。每次最多 20 段并明确提示截断；后端查询 5 秒超时。

区分已发送、待处理、失败、缺少请求记录、仅本地曾确认、身份不符、不可查询和无法确定。未查到不等于未发送，failed 不证明微信没有实际发出，sent 不等于对方已收到。响应不包含正文、请求标识或后端错误原文。查询不发送消息、不写发送映射、不结束轮次、不恢复记忆；原“核查后结束”仍需暂停与明确确认。

## 安全等待阶段的确认续处理

新增 POST /runtime/turns/resume（沿用站点认证/来源检查）和运维页“继续处理”按钮。仅新版本记录的 interruptedState=queued、phase=debounce、未登记任何出站、最近 5 分钟内的当前群非自身文字消息可继续。received 状态可能已执行部分入站逻辑，processing 可能有模型/记忆副作用，均不自动重放；旧记录不能证明原阶段时也不开放。

用户必须先启用机器人，并逐条确认可能产生模型调用及群回复。服务拒绝过期/旧预览、未确认、维护中、业务忙或重复恢复；调用原业务前先持久化 recoveryAttempts=1 与 recovery_dispatch 状态。恢复最多一次，再次异常退出转人工核查。复用原队列、回复策略和模型路径，已有上下文按消息 ID 去重，不重新执行整套入站副作用；仍可因当前策略选择不回复。不提供开机自动回复旧消息，也不续发部分完成的回复。

## 轮次容量统计与归档

运维页新增“运行记录容量”。GET /runtime/storage 返回未归档/已归档轮次数、记录总字节、发送映射总数/已确认/未确认及文件字节；不返回消息正文。超过 1 万条未归档轮次/发送映射，或轮次总字节达到 50 MiB，显示维护提醒。POST /runtime/storage/compact 沿用认证和来源检查，需先暂停且业务/UI 空闲、无其他维护，confirm=true 和预览摘要一致。

每批最多 100 条，限最后更新超过 30 天的 completed/skipped，needs_review/received/queued/processing 全部保留。先将原 JSON 完整 gzip 写入 turns/archive 并 fsync，再把原文件原子替换成含 ID、群、状态及压缩内容摘要的去重标记；无永久删除。重启验证归档存在及摘要后不将正文载入内存，旧消息再次投递时仍拒绝重复处理。归档中断时保留原文或已完成的归档，存储故障阻断消费，禁止清目录重建。

归档后保持暂停；仅将本批旧轮次移出业务内存，文件数量及永久总容量并非有界，不承诺必然释放磁盘。发送映射不清理，未确认状态和稳定请求键完整保留。后续拆分冷发送索引及永久保留/删除策略需另做设计；不要手工删除压缩归档、去重标记或 send-requests.json。此归档是用户确认的数据维护能力，不是例行云端发布备份，本次发布不主动替用户执行归档。

## 轮次过程、文字参数与成员改名联合适配

GET /runtime/turns/recent 返回最近 50 条未归档消息的状态、原因、批次及最多 40 个阶段事件，不返回消息正文。记录接收、合并、判断、模型与检索、模拟打字、发送等待/确认、拆句间隔和结束。合并批次共享业务阶段；发送阶段包含出站队列和确认，不借用全局最近一次发送耗时。旧记录无完整采集时不显示总耗时，中断区间未知，恢复后仍不伪称纯执行耗时。周期记忆提炼是独立任务，不虚称每轮都做提炼。

新增可配置 quietAllow、maxReplyChars、humanSilence、humanPunctStyle、humanFiller，沿用原业务语义与默认值。humanFiller 依赖 humanPunctStyle；backfillLimit 用于下一次建立上下文，0 不回补；contextMessages=0 不把全部历史误传作上下文。修复 Linux 安静时段拒绝后仍交模型的路径，以及接入查询忽略 limit 的问题。GET /runtime/text-config 返回服务端生效值和依赖说明；配置写入失败撤回内存修改，不伪报保存成功。真实 @、稍后主动回复及主动行为专用参数继续禁用。

identities.mjs 将当前群观察到的昵称及人工确认映射保存在 BOT_DATA/member-identities.json。启动仅从当前群已有上下文读取昵称，不改业务文件。GET /runtime/identities；POST /preview 生成精确版本预览；POST /commit 要求确认、预览未变、暂停及业务/UI 空闲，完成后保持暂停。映射将新昵称未来的 sender 设为旧昵称原稳定 ID，因此原亲密度、关系和按 ID 关联的逻辑继续使用旧身份；为回复模型补充管理员确认的映射资料。历史原文及已形成的两份关系不改写或静默合并。解除只影响后续，不撤销此前记忆变化；拒绝链式重绑、循环、未知目标和跨群文件。同名成员不能可靠区分，不能靠这个功能自动辨认。映射读写损坏阻断消费/发送并显示诊断错误。

验证覆盖参数保存失败及重启、真实业务的安静时段不调用模型/发送、映射后关系键保持一致、上下文不重复、中断不编造耗时。均使用模拟模型和接入，不故意中断真实微信群。页面交互验收由用户完成。
